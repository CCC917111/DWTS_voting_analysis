# DWTS 投票机制复现与审计

**从公开评分和淘汰结果出发，研究隐藏票数能被推断到什么程度，以及规则变化会怎样影响结果。**

[English README](README.md) · [完整结果](docs/RESULTS.md) · [运行指南](docs/REPRODUCING.md)

这是基于 v5 的独立、AI 辅助重建项目，方法参考 Team 2627761 的 2026 MCM Problem C 报告。它保留原报告归属，不宣称是原作者源码，也不宣称整篇数值已经复现。当前使用者与原团队的关系、贡献署名和许可证仍待确认。

## 项目价值

- 把论文方法整理成可运行、可测试、可审计的 Python 软件
- 同时保留 PyMC 参考实现与经过数值对照的 Numba MH 引擎
- 修正浮点并列排序，以及舞伴身份被注释/姓名别名拆开的具体问题
- 用按赛季分组的嵌套交叉验证检查回归与分类任务
- 把可证实的结论、重建假设和未解决的数值差距分开呈现

## 先跑一个不需要真实数据的小例子

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v4-verified.txt
python -m pip install --no-deps -e ".[test,audit]"
python -m dwts.demo --out outputs/my-demo
python -m pytest -q
```

已验证环境为 Python 3.12。Windows PowerShell 的激活命令是 `.venv\Scripts\Activate.ps1`。

例子里四位选手和票数均为虚构；不下载数据，不拟合模型。相同输入、评委与粉丝各占一半时，名次法淘汰 A，百分比法淘汰 C。输出包含 CSV、JSON 和 SVG。已有输出目录不会被覆盖。

默认测试只运行自包含测试；依赖官方数据或历史实验的测试会明确排除，不会冒充已通过。[验证记录](docs/VALIDATION.md)区分了本仓库验证和 v5 历史的 134 项测试。

## 真实结果与未解决问题

以下是 v5 已保存的实验结果，不是上面演示产生的：

|任务|v5 R²|报告 R²|v5 RMSE|报告 RMSE|
|---|---:|---:|---:|---:|
|评委均分|0.434488|0.146|1.100571|5.320|
|推断粉丝份额|0.555199|0.614|0.063604|0.072|

共 34 季、2,777 个选手周，使用五折外层赛季分组验证。评委与粉丝 RMSE 单位不同；作者实际评估定义未完全确认，因此不能将表格当作公平的模型排行榜。粉丝 R²/RMSE 的差距仍未解释。

这些结果属于回顾性潜变量分析：真实粉丝票数不可见，不能说“真实票数预测准确”；全季后验包含未来信息，不能说已经具备上线预测能力；SHAP 也不能证明职业舞伴的因果作用。
